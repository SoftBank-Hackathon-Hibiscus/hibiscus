# 시연 순서

명령은 `parity/`에서 실행합니다. 실제로 재어 본 시간 (9/30, WSL2 노트북, 이미지 캐시 있는 상태):

| 명령 | 걸린 시간 |
| --- | --- |
| `python -m premortem demo --scenario state-loss` | 19.8초 |
| `python -m premortem demo --scenario binding --ai fixture` | 32.3초 |

둘 다 개발용 샘플 앱입니다. 화면에 reference 재생, fixture 같은 표시가 그대로 나오고, 말로도 그렇게 설명합니다.

## 시연 전에 할 것

1. 베이스 이미지 미리 받기: `docker pull python:3.12-slim` (현장 네트워크가 느릴 수 있음)
2. 두 명령을 한 번씩 미리 돌려서 빌드 캐시 만들어 두기
3. 남은 테스트 컨테이너 확인: `docker ps -a --filter label=premortem.owner=juyeong` 가 비어 있어야 함
4. 터미널 글자 크게, 창은 요약 10줄이 한 화면에 보이게
5. 미리 돌린 실행 폴더(`premortem/.runs/...`)의 report.md, review.md를 열어 두기. 실시간 실행이 안 되면 이걸로 보여 준다

## 60초 버전 (최종 발표, 팀 흐름 안에서)

실행하면서 말하면 시간이 빠듯하다. binding 명령 하나만 실행하고(32초), state-loss는 미리 돌린 결과를 보여 준다.

1. (미리 돌린 state-loss 요약을 띄워 두고) "같은 기록을 컨테이너 재시작과 교체 상황에서 다시 보내 봤습니다. 재시작은 6건 다 맞는데, 컨테이너를 새로 바꾸면 6건 중 4건만 맞습니다. Cloud Run처럼 인스턴스가 바뀌면 데이터가 사라지는 걸 배포 전에 잡는 겁니다."
2. binding 명령 실행 → 기다리는 동안 "이 앱은 개발 PC에서는 되는데 컨테이너 안에서는 127.0.0.1에만 열려 있어서 밖에서 접속이 안 됩니다."
3. 결과가 나오면 "AI가 코드 한 줄을 고쳤고, 그 수정은 검사를 거쳐 복사본에만 들어갔습니다. 같은 기록으로 처음부터 다시 돌려서 전부 통과했고, 사람이 보기 전까지는 원본에 안 들어갑니다."

## 3분 버전 (중간보고)

1. state-loss 실행 (20초). restart 6/6, replace 4/6 → report.md에서 4, 5번 불일치와 "새 컨테이너 ID, 같은 이미지" 증거를 보여 준다
2. binding 실행 (32초). 수정 전 none 실패 이유(바깥 health 없음, 안에서는 성공, 127.0.0.1에서만 LISTEN) → review.md에서 diff 한 줄과 조건별 전후 표
3. 안전장치 한 줄씩: AI는 도구 없이 JSON만, Dockerfile·정책·테스트는 못 고침, 복사본에만 적용, 기준 기록은 안 바꿈
4. 아직 안 된 것: 윤선님 재생기, 류진님 계약과의 연결, 실제 AI 호출. 말로 먼저 밝힌다

## 실패했을 때

- Docker가 안 뜨면: 미리 돌린 report.md, review.md를 보여 준다
- AI 단계: 실제 호출을 한 번이라도 해서 녹화해 두었다면 `--ai recorded --analysis-file examples/premortem/recordings/<파일>`로 보여 준다(화면에 "녹화된 실제 응답"으로 나옴). 한 번도 못 했으면 `--ai fixture`로 보여 주고 "AI 응답 예시"라고 말한다
- 시연 PC와 OS는 팀이 정한 것 하나로. 윤선님 데모는 Windows PowerShell 기준이라 리허설 때 맞춰 본다

## 통역 스크립트용 문장 (10/4 13:00 제출)

- 같은 사용 기록을 컨테이너를 재시작했을 때와 새로 바꿨을 때 다시 보내 봤습니다.
- 재시작하면 데이터가 남지만, 새 컨테이너로 바뀌면 사라집니다. 클라우드에서 인스턴스가 바뀔 때 생기는 문제를 배포 전에 찾습니다.
- AI가 앱 코드를 한 줄 고쳤고, 그 수정은 검사를 거쳐 복사본에만 적용됐습니다.
- 같은 기록으로 처음부터 다시 확인해서 전부 통과했습니다. 원본에 넣는 것은 사람이 확인한 뒤입니다.
